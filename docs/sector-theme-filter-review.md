# SectorFilter & ThemeFilter 深度审查

2026-05-07

---

## 总体判断

**SectorFilter 当前 L1 版本有结构性缺陷**——它衡量的是"这只股票在不在一个强行业里"，而短线选股需要的是"这只股票自身是否值得交易"。行业 β 不能替代个股 α。当前 L1 + 无个股过滤的形式不应继续作为独立加分维度。改造为 L2 粒度 + 行业内领涨过滤后，可保留低权重正向确认功能。

**ThemeFilter 方向正确但实现有实质性缺口**——三个子信号的共线性导致"强者通吃"，缺乏时间维度过滤不了一日游，资金信号粒度太粗浪费了数据中的信息。骨架可保留，但需要补全。

---

## 一、SectorFilter — 结构性缺陷

### 1.1 核心问题：衡量了不该衡量的东西

```
当前逻辑：股票所属申万一级行业涨幅排名 TOP 5 → 加分
实际含义：这只股票碰巧在一个今天涨得多的行业里
```

这个逻辑在**行业 ETF 轮动策略**中是合理的——你要的就是行业 β。但在**个股短线选股**中，最终买的是单只股票，不是行业 ETF。行业强 ≠ 行业内个股有交易价值：

- 行业涨 3%，可能是 2 只权重股贡献了 80% 的涨幅，其余 200 只股票平均涨 0.5%
- 当前逻辑给这 200 只"被平均"的股票和龙头股**完全相同的行业加分**
- 这些跟涨股在次日的表现与龙头股天差地别

这不是参数问题，是**信号定义问题**。一个只衡量"行业归属 + 行业涨幅排名"的信号，本身就不足以构成个股短线选股的独立维度。

### 1.2 行业内部未做任何区分

`index_member` 表实际有 `l1_code/l2_code/l3_code` 三级行业代码，但当前 `repo.get_index_member_l1_map` 只读取 L1，且未利用行业内个股的相对表现信息。一只股票在行业内的相对表现（是否领涨、是否放量、是否率先涨停）完全没有进入打分。

一个更可靠的行业维度至少应该：
- 判断股票是否是**行业内当日涨幅领先**的个股（领涨 vs 跟涨）
- 判断股票的**成交额在行业内的相对分位** + **相对自身 20 日量比**（避免绝对成交量天然偏向大市值股票）
- 如果行业强但个股弱（缩量滞涨），不应该加分甚至应该减分

当前实现把这些信息全部丢弃了。

### 1.3 粒度问题：31 个一级行业对 A 股短线太粗

A 股短线热点从来不是"医药生物涨了"，而是"CRO 反弹了"或"中药出政策了"。31 个 L1 行业的颗粒度下：
- TOP 5 覆盖了 ~16% 的行业，对应 800-1500 只股票
- 这已经不是一个"筛选"信号，而是一个"普撒"信号
- 真正有区分度的热点（人形机器人、HBM、低空经济）都在 L2/L3 甚至更细的级别

此问题**本身就可解**——`index_member` 表里有 L2 和 L3 代码，下沉粒度只是配置和数据查询的改动。不改的唯一原因是"选择不做"，不是"做不到"。

### 1.4 缺失负向信号：逻辑不完整

A 股板块轮动特征显著——今天 TOP 1 明天垫底并不罕见。当前逻辑：
- 行业 TOP 5 → 正向加分
- 行业 BOTTOM 5 → **什么都不发生**

一个完整的行业维度应该是双向判断：
- 行业强度高 → 对个股信号有**确认加成**
- 行业强度低 → 对个股信号有**削弱惩罚**

只做正向不做负向，等于放弃了一半的信息。而且负向信号的可靠性往往比正向更高——弱势行业里走出强势个股的概率，远低于强势行业里走出弱势个股的概率。

## 二、ThemeFilter — 方向正确，实现有缺口

### 2.1 核心设计是合理的

ThemeFilter 的基本架构没有问题：
- 多数据源交叉验证（涨幅 + 涨停 + 资金）
- 跨概念取 max 而非累加（防止概念堆砌套利）
- 渐进降级（部分数据缺失仍可运行）

这三个设计决策都是正确的。

### 2.2 问题一：三个子信号共线性导致"赢家通吃"

这是当前最影响**可靠性**的问题。

三个子信号——概念涨幅排名、涨停最强排名、概念资金净流入——在 A 股高度正相关：

```
概念 A（涨幅 #1，涨停最多，资金大幅流入）：
  rank_bonus(50) + limit_bonus(50) + moneyflow(15) = 115 → cap 100

概念 B（涨幅 #3，涨停适中，资金小幅流入）：
  rank_bonus(35) + limit_bonus(35) + moneyflow(15) = 85

概念 C（涨幅 #8，无涨停密集，资金微流入）：
  rank_bonus(12) + limit_bonus(0) + moneyflow(15) = 27
```

看起来梯度合理。但如果考虑一个关键场景：

```
概念 D（涨幅 #4，涨停排名未进前 10，但资金大幅流入）：
  rank_bonus(28) + limit_bonus(0) + moneyflow(15) = 43
```

概念 D 的情况是"涨了但不是涨停潮，资金在默默流入"——这恰恰可能是**次日爆发的前兆**，比概念 A 的"已经全面爆发"更有短线价值。但在当前打分下，43 vs 100，概念 D 被完败。

问题不在于信号相加，而在于**三者高度共线时，加法放大了领先者的优势，压制了"部分信号强"的潜在标的**。这在逻辑上违背了"多信号独立验证"的设计初衷——实际行为是"同信号三次确认"。

**修正方向**：不是取消加法，而是降低共线信号的叠加权重。例如概念涨幅排名和涨停排名的相关性最高，可以考虑二者取 max 而非 sum；资金流作为相对独立的维度保留加法。

### 2.3 问题二：无时间维度，无法过滤一日游

A 股概念炒作中，一日游极其常见。某概念因为一条盘中消息拉涨 4%，次日全部回吐。

当前 ThemeFilter **只看当日快照**。一个连续 5 天在 TOP 3 的持续性热点，和一个今天刚冒出来的脉冲热点，在打分上没有区别。

而 SectorFilter 至少有一个 3 日均涨幅的趋势加成。ThemeFilter 缺失时间维度是一个**功能不完备**的问题。

至少需要：
- 概念是否连续 N 日在 TOP 10（持续性确认）
- 概念排名是否在改善（今日 vs 昨日 rank 变化，动量信号）

### 2.4 问题三：资金信号粒度浪费了数据

```python
mb = 15 if net_amount > 0 else 0
```

`net_amount` 是**亿元**单位的连续值。当前把它压缩成一个二元信号：
- 净流入 100 亿 → 15 分
- 净流入 0.01 亿（100 万）→ 15 分
- 净流入 -50 亿 → 0 分

100 万对概念板块是噪音，不能和 100 亿同等对待。这不是投入问题，是**数据使用不充分**的问题。数据本身有量级信息，代码把它扔掉了。

此外，负值完全没有利用。一个概念净流出 50 亿是非常强的负向信号，当前完全忽略。

### 2.5 问题四：分档表后半段失去区分度

```python
ths_rank_bonus = {1:50, 2:42, 3:35, 4:28, 5:22, 10:12}
# rank 6-10 → 全部 12 分
```

TOP 10 里后 5 名（6-10）完全同分。第 6 名（可能涨 3%）和第 10 名（可能涨 1.5%）的差异被抹平。在 A 股，3% 和 1.5% 的概念涨幅差异不小。

### 2.6 问题五（次要）：多概念共振信号被丢弃

一个同时沾边 3 个中等强度概念（各 30-40 分）的股票，和一个只沾边 1 个强概念（100 分）的股票，前者可能有更高的参与确定性（多个独立主题驱动）。当前 max 策略把这个信号完全丢弃。

这个问题不急着修——防止概念堆砌套利比捕捉共振更重要。但可以设计一个安全的小额加成（如次强概念 >30 分时 +5），不影响防套利的核心逻辑。

## 三、两个 Filter 的关系

### 3.1 权重分配

```
sector:  0.10 × 100 = 最多 10.0
theme:   0.10 × 100 = 最多 10.0
limit:   0.25 × 100 = 最多 25.0
moneyflow: 0.25 × 100 = 最多 25.0
lhb:     0.20 × 100 = 最多 20.0
```

权重结构本身合理——个股信号高权重，板块信号低权重。这不是问题所在。问题是**在低权重下，SectorFilter 的信号噪音比是否值得保留它**。

### 3.2 共振日——SectorFilter 拖后腿的场景

共振日（同一行业的股票同时拿到 sector + theme 高分）看似"确认"，实则旧版 SectorFilter 在做无用功：行业强 → 行业内的概念也强 → ThemeFilter 已经捕捉到了。旧版 SectorFilter 没有增加新信息，只是给同一批股票多加了 7-10 分。

分离日（冷门行业 + 热门概念，如化工股沾边固态电池）才是 ThemeFilter 独立价值的体现。而 SectorFilter 在分离日要么做不了贡献（行业不在 TOP 5），要么做错误贡献（行业强但个股弱）。

## 四、改进方案

以下按**系统可靠性 / 完备性 / 可用性**排序，不按投入大小。

### 4.1 ThemeFilter 子信号去共线（可靠性）

**问题**：三信号高度共线时加法退化成同源重复计分。直接取 max 又会过度削弱"涨幅榜 + 涨停榜双确认"的强题材——A 股短线中，涨停家数和连板高度本身就是独立的情绪强度信号，不完全等同于概念指数涨幅。

**方案**：折扣叠加——涨幅排名和涨停排名各保留但降权较低的一方。

```
修改前：score(concept) = rank_bonus + limit_bonus + moneyflow_bonus
修改后：score(concept) = max(rb, lb) + 0.3 × min(rb, lb) + moneyflow_bonus
```

理由：
- max 保留主导信号，0.3 折扣保留"双确认"的额外信息
- 涨停潮确实有独立于涨幅排名的信息量（涨停家数反映游资参与度），不应完全丢弃
- 资金流是不同性质的数据（真金白银），独立加法合理
- 不影响渐进降级（哪个信号有就用哪个）

**影响示例**（moneyflow_bonus 按 4.3 排名分位方案，假设概念资金流排前 5 取 20）：

| 场景 | 折扣前 (sum) | 折扣后 (max + 0.3×min) |
|------|-------------|------------------|
| 概念 A（涨幅 #1 + 涨停 #1 + 资金流入 top5） | 50+50+20=120→cap100 | 50+0.3×50+20=**85** |
| 概念 D（涨幅 #4，无涨停排名，资金流入 top5） | 28+0+20=**48** | 28+0+20=**48** |
| 概念 A : 概念 D 比例 | 100:48 ≈ 2.1:1 | 85:48 ≈ 1.8:1 |

中等强度概念的相对竞争力提升，但双确认信号仍保持明显优势。

### 4.2 ThemeFilter 增加短线轻量时间维度（完备性）

**问题**：只看当日，无法区分持续热点和一日游。

**约束**：短线策略的超额收益集中在概念首次爆发的 1-2 天。连续 3/5 日 TOP 10 的持续性确认会把系统从"短线启动捕捉"推向"波段持续性确认"，与已有 `ThemeSwingFilter` 职责重叠。

**方案**：只加两个轻量时间信号，不做大权重持续性加成——

1. **昨日也上榜**：概念昨日也在 ths_daily 的 TOP 10 → +5（确认不是第一天冒出来的孤立脉冲）
2. **排名改善**：今日 ths_rank 较昨日上升（如从 #8 → #4）→ +5（动量改善信号）

```
concept_temporal_bonus:
  yesterday_in_top_n: 5    # 昨日也在 TOP 10
  rank_improvement: 5      # 排名较昨日上升（今日 rank < 昨日 rank）
```

数据已在表中（ths_daily 按日存），repo 加一个查昨日排名的查询即可。

### 4.3 ThemeFilter 资金流分档 + 负向（可用性）

**问题**：连续值被二元化，丢弃量级信息；负向完全未用。

**额外约束**：A 股概念板块规模差异巨大。"中字头"概念的成分总市值可能是"低空经济"的几十倍，直接使用绝对净流入阈值（1/5/10 亿）会系统性偏向大市值、大成分数题材。同样的 5 亿净流入，对小概念是巨量资金确认，对大概念只是背景噪音。

**方案**：资金流按当日概念排名/分位数打分，而非绝对金额阈值。

```yaml
concept_moneyflow:
  # 按 net_amount 在所有概念中的排名分位打分，且必须通过正负号门槛
  # 正向：net_amount > 0 且排名前 N 才加分
  # 负向：net_amount < 0 且倒数前 N 才扣分
  inflow_positive_rank_top_5:   {score: 20}   # net_amount > 0 且流入排名前 5
  inflow_positive_rank_top_10:  {score: 12}   # net_amount > 0 且流入排名前 10
  inflow_positive_rank_top_20:  {score: 5}    # net_amount > 0 且流入排名前 20
  outflow_negative_rank_bot_5:  {score: -15}  # net_amount < 0 且流出排名前 5（倒数）
  outflow_negative_rank_bot_10: {score: -8}   # net_amount < 0 且流出排名前 10
```

正负号门槛是必须的：如果全市场概念普遍净流出，rank_top_5 可能只是"流出最少"的概念，实际 net_amount 仍为负。不加门槛会在资金全面退潮时给"相对不差"的概念错误加分。

或者备选方案——用归一化指标：

```yaml
concept_moneyflow_normalized:
  # net_amount / company_num（平均每成分股净流入，亿元/股）
  per_stock_inflow_gt_0_1:   {score: 20}   # 平均每只成分股净流入 >0.1亿
  per_stock_inflow_gt_0_05:  {score: 12}
  per_stock_inflow_gt_0_01:  {score: 5}    # 过滤噪音
  per_stock_outflow_lt_-0_1: {score: -15}
```

推荐排名分位方案——不依赖 company_num 字段的准确性，也天然适应概念规模差异。

净流入在所有概念中排名 20 名开外的，视为无显著资金信号，不给分。

### 4.4 SectorFilter 下沉到 L2 + 行业内领涨识别（可靠性）

**问题**：L1 太粗 + 行业内一视同仁 = 信号不具可交易性。

**方案**：

1. **粒度下沉到 L2**：`index_member` 表已有 `l2_code` 字段，将行业池从 31 个扩展到 ~100 个。`repo` 层新增 `get_index_member_l2_map`，SectorFilter 内部将 TOP N 取值和排名逻辑从 L1 切换到 L2。

   **top_n 重新校准**：L1 取 TOP 5 / 31 ≈ 16%；L2 ~100 个行业若仍取 TOP 5 仅覆盖 5%，过窄。调整为 `top_n_l2: 10`（覆盖 10%，与 L1 的 16% 接近但更精细），或按百分比 `top_pct_l2: 0.10`。

2. **行业内领涨识别**：一只股票除了要在强势 L2 行业里，还需要通过个股层面的确认——

```
领涨条件（需同时满足至少 2 项）：
  a. 当日个股涨幅在所属 L2 行业内排名前 30%（涨幅分位）
  b. 当日个股成交额在所属 L2 行业内排名前 30%（成交额分位，非成交量绝对值）
  c. 当日个股成交量相对自身 20 日均量 ≥ 1.5 倍（相对量比，消除股本差异）
```

注意不单独使用成交量绝对值排名——工商银行的成交量永远大于任何小市值股票，绝对量排名对大票天然有利，失去了行业内领涨识别的意义。

**领涨条件的相关性验证**：涨幅分位和成交额分位在 A 股有较强正相关（涨得多的股票通常成交也放大）。如果二者相关性过高，"≥2 项"可能退化为"涨幅前 30% + 量比 ≥1.5"，成交额条件形同虚设。回测时需计算三个条件两两相关系数，若涨幅与成交额分位的相关性 > 0.7，考虑将成交额条件替换为其他独立维度（如换手率分位、日内振幅分位）。

**小样本 L2 行业保护**：部分 L2 行业成分股很少（如 5-10 只），前 30% 可能只有 1-3 只，排名极易受单日波动影响。

- 成分数 < 5：**跳过领涨条件检查**，直接给 `leadership_factor = 1.0`。行业太小，分位排名无统计意义，行业强弱本身已足够作为信号。
- 成分数 5-10：领涨条件改用绝对排名兜底 `max(前 30%, 前 3 只)`，但保留 ≥2 项规则。
- 成分数 > 10：使用标准领涨条件（前 30% + 成交额分位 + 量比，≥2 项）。

这样小样本行业不会因为"满足不了 ≥2 项"而全体拿 0 分。

```
raw_score(stock) = (sector_rank_bonus + trend_bonus) × leadership_factor
score(stock) = raw_score / 70 × 100
leadership_factor:
  1.0  满足 ≥2 项领涨条件
  0.0  满足 <2 项（行业强但个股无领涨特征 → 不加分）
```

简化为二档（1.0 / 0.0），不做 0.5 中间档。原因：sector 权重仅 0.10，0.5 档与 1.0 档在最终综合分中的差距约为 `0.10 × rank_bonus × 0.5 ≈ 1-2 分`，对最终排名几乎无影响。核心价值在 0.0 档——彻底筛掉跟涨股，这个已经做到。

### 4.5 SectorFilter 不启用负向扣分（简化）

弱势行业不再输出负分，统一视为 `sector=0`。固定分母下，弱行业股票相对强势
行业领涨股天然少拿 5-10 分，已经形成足够区分；额外负分在 `sector` 0.10 权重下
边际影响有限，却会破坏 filter 统一的 0-100 分契约，并把只有弱行业信号的股票带入
综合候选池。

因此 SectorFilter 保持纯正向确认角色：强 L2 + 行业内领涨才加分，否则不写入该维度。

### 4.6 `_bonus_from_table` 分档细化（可用性）

**问题**：rank 6-10 无区分度。

**方案**：

```yaml
ths_rank_bonus:

  10: 6    # rank 8-10
```

### 4.7 SectorFilter 定位重新审视（架构）

做完 4.4 + 4.5 后，SectorFilter 才真正具备可靠的个股区分能力。

需要注意的是，ThemeFilter 不能完全替代行业维度。A 股中券商、银行、煤炭、有色、地产链等行业 β 阶段性很强，且这些行业的行情驱动逻辑（政策、商品价格、利率）不一定会通过 THS 概念准确表达。THS 概念更擅长捕捉主题/题材类热点，对传统周期行业的覆盖不如申万行业分类体系。

**结论**：保留 SectorFilter 的低权重正向确认功能，但必须加入 L2 粒度 + 行业内领涨过滤。不走纯负向角色路线。

## 五、实施顺序

每轮完成后跑对比回测，确认方向正确再继续。4.3（资金流排名）和 4.1（折扣叠加）共同决定 ThemeFilter 的分数分布，应作为原子变更一起上线，分开回测的中间态 baseline 会失真。

**第一轮（ThemeFilter 核心修复，原子变更）**：

1. **ThemeFilter 资金流改为排名分位打分 + 正负号门槛**（4.3）+ **子信号去共线（折扣叠加）**（4.1）— 一起改，一起测
2. **回测对比**：新旧版本 TOP 20 差异、次日平均收益、概念集中度
3. **ThemeFilter 短线轻量时间维度**（4.2）+ **分档细化**（4.6）
4. **回测对比**：确认 ThemeFilter 全部改动后的综合效果

**第二轮（SectorFilter 结构性改造）**：

5. **SectorFilter 下沉 L2 + 领涨识别**（4.4）— 改动大，单独跑回测
6. **回测对比**：确认 Sector 改动后的候选池质量和集中度

**第三轮（全局调参）**：

7. 根据回测结果调整权重（如 L2 下沉后 sector 权重是否需要微调）
8. 最终全量回测确认
