# 资金流价格确认机制

## 背景问题

Tushare `moneyflow` 接口按**主动买卖方向**判定资金流向。当股票跌停或持续下跌时，卖盘挂单被买盘主动成交，算法会将其计为"主力净流入"，但这实际上是**承接卖盘**而非主动建仓。直接使用会导致大量下跌股票因"假净流入"进入选股结果。

## 解决方案

用 `daily_kline.close > daily_kline.open`（日内收阳）作为价格确认门槛，筛选掉日内收阴的"假流入"信号。

### 为什么用 `close > open` 而不是 `pct_chg > 0`

| 场景 | open | close | pct_chg | close>open | 真实情况 | 哪个对 |
|------|------|-------|---------|------------|----------|--------|
| 低开高走，收盘仍绿 | 9.5 | 9.9 | -1% | ✅ 保留 | 利空低开后资金承接拉回 4%，真实买盘 | `close>open` |
| 高开低走，收盘仍红 | 10.3 | 10.05 | +0.5% | ❌ 过滤 | 高开借利好出货，日内持续回落 | `close>open` |
| 单边下跌 | 10.0 | 9.5 | -5% | ❌ 过滤 | 纯粹接飞刀 | 都行 |
| 单边上涨 | 10.0 | 10.5 | +5% | ✅ 保留 | 真金白银主动买入 | 都行 |

`pct_chg` 是相对昨收的涨跌幅，反映不了日内博弈；`close > open` 更贴合"当天买盘是否在主动推升价格"这个核心判断。

## 共享工具函数

代码位置：`src/mo_stock/filters/moneyflow_utils.py`

### `has_price_confirmation(open_price, close_price, min_intraday_pct=0.0)`

```python
def has_price_confirmation(open_price, close_price, min_intraday_pct=0.0) -> bool:
    if open_price is None or close_price is None or open_price <= 0:
        return False
    intraday_pct = (close_price - open_price) / open_price * 100
    return intraday_pct > min_intraday_pct  # 默认 close > open
```

- `open_price <= 0`：防御性 guard，防止除零
- `min_intraday_pct` 预留阈值参数，当前为 0（即 `close > open` 即可）

### `confirmed_positive_net(net_mf_wan, open_price, close_price, min_intraday_pct=0.0)`

```python
def confirmed_positive_net(net_mf_wan, open_price, close_price, min_intraday_pct=0.0) -> float:
    net = net_mf_wan or 0.0
    if net <= 0:                                          # 净流出 → 保留原值
        return net
    if has_price_confirmation(open_price, close_price):   # 正净流入 → 需确认
        return net
    return 0.0                                            # 正净流入无确认 → 归零
```

核心规则：

| 净流向 | 日内形态 | 结果 |
|--------|----------|------|
| 净流出（≤0） | 任意 | 保留原负值 |
| 正净流入 + 收阳 | `close > open` | 保留原值 |
| 正净流入 + 收阴 | `close ≤ open` | 归零（不认） |

## 短线策略：MoneyflowFilter

代码位置：`src/mo_stock/filters/short/moneyflow_filter.py`

### 当日判断

```python
# 1. 净流出直接跳过
if net_mf_wan <= 0:
    continue

# 2. 正净流入必须有价格确认（close > open）
if not has_price_confirmation(open_price, close_price):
    continue  # 日内收阴，不入资金流榜单
```

- 当日的 `open/close` 来自 `daily_kline` 表，与 `amount`（成交额）一次查询获取
- 通过确认后，计算 `today_bonus`（净流入占成交额比例分档加分），并记录 `intraday_pct` 供调试

### 近 3 日滚动累计

```python
def _get_confirmed_moneyflow_rolling_sum_map(session, end_date, days=3):

    for ts_code, net_mf_amount, open_price, close_price in rows:

```

**逐日独立确认，然后累加**：

| 交易日 | open | close | 日内 | net_mf（万元） | 计入值 |
|--------|------|-------|------|---------------|--------|
| D-2 | 10.0 | 9.5 | 收阴 | +2000 | **0**（正流入不认） |
| D-1 | 9.5 | 9.8 | 收阳 | -500 | **-500**（净流出保留） |
| D0 | 9.8 | 10.5 | 收阳 | +3000 | **+3000**（正流入确认） |
| **滚动累计** | | | | | **+2500** |

- 净流出无论哪天都保留，负贡献不归零
- 正净流入只在当日 `close > open` 时才计入
- 累计 > 0 触发 `rolling_3d_bonus`（+20）
- 使用 OUTER JOIN，若某日 DailyKline 缺失则 `open/close` 为 None → 视为无确认 → 正净流入归零

## 波段策略：MoneyflowSwingFilter

代码位置：`src/mo_stock/filters/swing/moneyflow_swing_filter.py`

### 数据准备

```python
# 一次查询 10 日内所有 DailyKline 的 open/close
price_map: dict[(ts_code, date), (open, close)]

# 每条 Moneyflow 记录逐日过 confirmed_positive_net
sum5 = sum(confirmed_positive_net(r.net_mf_amount, *price_map[(r.ts_code, r.trade_date)])
           for r in items if r.trade_date in dates5)
```

### 聚合口径

| 指标 | 计算方式 | 用途 |
|------|----------|------|
| `sum5` / `sum10` | 逐日 `confirmed_positive_net` 后累加 | 5/10 日累计净流入 > 0 各 +25 |
| `positive_days_5d` | 近 5 日内 `net > 0` 且 `close > open` 的天数 | ≥3 天 +20 |
| `unconfirmed_inflow_days_5d` | 近 5 日内 `net > 0` 但 `close ≤ open` 的天数 | ≥2 天触发 -20 惩罚 |
| `big_positive_days` | 大单净买入且 `close > open` 的天数 | 占比 ≥50% +20 |

### 评分结构

```
sum5 > 0          → +25
sum10 > 0         → +25
positive_days5 ≥ 3 → +20
大单正向占比 ≥ 50% → +20
小单买大单卖      → -30
unconfirmed ≥ 2天  → -20（新增）
─────────────────────────
clamp(0, 100)
```

### 与短线的差异

| 维度 | 短线 | 波段 |
|------|------|------|
| 未确认的正净流入 | 直接排除该股票 | 归零但不排除，单独统计 |
| 惩罚机制 | 无 | ≥2 天 -20 |
| 原因 | 短线需要动量确认，不赌反弹 | 波段容忍回调中的试探性买盘，但连续未确认视为危险信号 |

## 数据依赖

所有价格确认依赖 `daily_kline` 表的 `open` 和 `close` 字段：

```
daily_kline:
  open   Float  开盘价
  close  Float  收盘价（前复权前原始价）
```

查询方式：
- **短线当日**：`select ts_code, amount, open, close from daily_kline where trade_date = :date`
- **短线滚动**：`Moneyflow LEFT JOIN DailyKline ON (ts_code, trade_date)` — OUTER JOIN 防御缺失
- **波段**：`select ts_code, trade_date, open, close from daily_kline where trade_date in (:dates10)`

  # 价格确认规则写在代码中：正净流入必须满足 daily_kline.close > daily_kline.open。
  # 日内收阴的正净流入常是承接卖盘，不作为主动建仓信号。

```yaml
dimension_weights:
  moneyflow_swing: 0.20  # 正净流入必须有价格确认；日内收阴净流入不推高资金持续性分
```

## 后续调参方向

当前 `min_intraday_pct = 0.0`（即 `close > open` 即可），未加阈值。如果后续回测发现十字星噪音（`close` 仅比 `open` 高 0.01 元）影响信号质量，可改为：

```python
# close >= open * 1.002，即日内涨幅 ≥ 0.2% 才算确认
has_price_confirmation(open_price, close_price, min_intraday_pct=0.2)
```

`confirmed_positive_net` 和 `has_price_confirmation` 都已预留 `min_intraday_pct` 参数，无需改接口。
